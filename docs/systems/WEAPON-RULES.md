# กติกาอาวุธ ความชำนาญ ร้านช่าง และของยูนีค

เอกสารนี้แยก **กติกาที่ผู้ใช้ยืนยัน** ออกจาก **ข้อเสนอ/แบบจำลองเพื่อทดสอบ** ยังไม่ได้เพิ่ม inventory, trade, drop, shops, durability หรือ mastery ลง runtime และไม่ได้ย้ายตัวละครเดิมไปใช้สูตรสเตตัสใหม่

## 1. เงื่อนไขสวมใส่

ยืนยัน: ทุกเผ่าใช้เกณฑ์เดียวกัน อาวุธระบุ requirement เช่น STR/DEX/INT และเลเวลตามชิ้น โบนัสจากอาวุธชิ้นนั้นไม่ช่วยให้ใส่ตัวมันเองได้ โบนัสสายเลือดอาจทำให้สายที่ถนัดเหลือแต้มไปลงค่าอื่น ผู้เล่นลงทุนแต้มเพื่อเล่นข้ามสายได้ ไม่มี race lock

ข้อเสนอสำหรับ simulation: eligibility ใช้ค่าฐาน + แต้มที่ลง + โบนัสสายเลือดที่ถาวร แยกจาก combat stats ที่รวมอุปกรณ์และบัฟทั้งหมด เพื่อหลีกเลี่ยงถอดชิ้นหนึ่งแล้วการสวมใส่ชิ้นอื่นพังต่อเนื่อง ข้อเสนอเรื่องโบนัสจาก **อุปกรณ์ชิ้นอื่น/บัฟชั่วคราว** ยังไม่ได้รับการยืนยัน ไม่ตีความว่าผู้ใช้อนุมัติข้อจำกัดเพิ่มแล้ว

ต้องตรวจ eligibility ที่ server เมื่อใส่ เปลี่ยน stat/reset เปลี่ยนสายเลือด (ถ้ามี) และทุกเส้นทางย้ายของเข้า slot ไม่ใช้ client ส่งค่า STR/DEX ที่เชื่อถือได้เอง

ตัวอย่างผู้ใช้ STR +1/level เป็นสมมติฐานเท่านั้น ไม่ใช่สูตรที่ยืนยันแล้ว ค่าปัจจุบันใน `shared/rules.ts` ยังเป็นฐาน 5, โบนัสเผ่า 3+floor((level−1)/5), 3 แต้มต่อเลเวล, allocated stat cap 60, level cap 50

## 2. ผลแบบจำลองสเตตัส (ไม่ใช่ผลบาลานซ์ combat)

รันซ้ำ: `node --import tsx scripts/progression-study.ts` ผลข้อมูลอยู่ `progression-study.json`

สมมติร่วม: ฐานทุกค่า 5; ได้ 3 แต้มต่อเลเวล; requirement หลักทดลอง ceil(8+0.6×level); ตั้ง allocated cap ทดลอง 120 เพื่อศึกษาได้ถึง Lv.100 (ไม่ได้เปลี่ยน cap จริง) ไม่มี gear/buff ใน calculation; ทุก stat ใช้ราคา 1 แต้มในแบบจำลองนี้

| เลเวล | เงื่อนไขอาวุธทดลอง | โบนัส +1/level: สายตรงจ่าย / ข้ามสายจ่าย | โบนัสโตช้า: สายตรงจ่าย / ข้ามสายจ่าย |
|---|---:|---:|---:|
| 20 | 20 | 0 / 15 | 9 / 15 |
| 50 | 38 | 0 / 33 | 21 / 33 |
| 100 | 68 | 0 / 63 | 41 / 63 |

สายตรงคือ stat ที่ตรง bonus ประจำเผ่า ข้ามสายคือใช้ stat ที่ไม่รับ bonus; ไม่ได้หมายถึงต้องถืออาวุธตามเผ่า

Lv.20 ภายใต้สมมติฐาน +1/level ตัวแดงเริ่ม STR=25 (ฐาน5+โบนัส20); ต้องการธนู DEX20 ลง DEX อีก15 แต้ม ยังเหลือ42จาก57แต้มที่ได้รับ ไม่ใช่ STR20 ตามตัวอย่างเดิมเพราะแบบจำลองนี้มีฐาน5

Lv.100 +1/level ให้โบนัส100 เทียบกับโบนัสโตช้า22 และประหยัดแต้ม requirement ในตัวอย่างได้63เทียบ22 นี่บอกต้นทุนการเข้าถึงอาวุธ ไม่ใช่บอกความแรงจริง: STR, DEX, AGI, VIT, INT, LUK ให้ประโยชน์ต่อ DPS/EHP/healing/utility ไม่เท่ากัน ต้องมี skills/crit/accuracy/armor/เศรษฐกิจจริงก่อนรับรองความสมดุลทั้ง6เผ่า

ทิศทางแนะนำ: ให้โบนัสเผ่าโตช้า มีงบแต้มรวมเท่ากัน และทดสอบ build งบเท่ากันถึง Lv.100 ก่อนเลือกสูตรสุดท้าย ไม่ยืนยันว่าโบนัสโตช้าตัวอย่างนี้เป็นคำตอบสุดท้าย ข้อเสนอเลเวล100ต้องออกแบบ cap/ราคาสเตตัสใหม่ร่วมกัน ไม่แอบใช้ cap60 เดิมแล้วสร้าง requirement ที่บางเผ่าไม่มีวันถึง

## 3. ความชำนาญอาวุธ: แบบฝึกทดลอง

ยืนยัน: เปลี่ยนสายได้ ไม่ลบความชำนาญเก่า ต้องลงทุนฝึกชนิดใหม่

ข้อเสนอ: เก็บ mastery แยกตาม character_id และ weapon_type (ไม่ใช่ตาม item instance) เปลี่ยนดาบคนละเล่มยังใช้ความชำนาญดาบเดิม แต่ดาบใหญ่/ดาบมือเดียวเป็นคนละประเภท

ให้คะแนนจาก **วินาทีที่มีการกระทำได้ผลจริง** บน server สูงสุด1แต้มต่อวินาทีสำหรับอาวุธโจมตีหนึ่งประเภท ไม่ใช่นับทุก hit: ดาเมจจริงกับเป้าหมายที่เข้าเกณฑ์, รักษา HP ที่ขาดจริง, บัฟที่มีประโยชน์จริง หรือกลไกที่ระบบระบุ โล่ฝึกจาก block/guard ที่รับผลจริงและอาจได้แต้มคู่มือหลักเมื่อป้องกันจริง ไม่ได้แต้มเพียงถือไว้

การตีอากาศ ศัตรูอมตะ heal เต็ม HP ร่ายบัฟซ้ำทับของเดิม และสลับอาวุธหลายชนิดในวินาทีเดียวไม่สร้างแต้มเพิ่ม หุ่นฝึกเสนอให้ช่วยเริ่มต้นถึง mastery10 เท่านั้น ต้องกำหนด eligibility ของ encounter, enemy difficulty, การฟื้น HP วน และเพดานจากเป้าหมายเดิมก่อนใช้จริง ไม่อ้างว่ากติกานี้กันบอทได้ทั้งหมด

แบบจำลองเวลา: cumulative XP ที่ rank m = 60m + 6m², capทดลอง100, 1XP/eligible second:

| Mastery | เวลาฝึกที่ได้เครดิตสะสม | เวลาเล่นเมื่อได้เครดิต60%ของเวลา |
|---|---:|---:|
| 10 | 20 นาที | 33 นาที20วินาที |
| 20 | 1 ชั่วโมง | 1 ชั่วโมง40นาที |
| 50 | 5 ชั่วโมง | 8 ชั่วโมง20นาที |
| 70 | 9 ชั่วโมง20นาที | 15 ชั่วโมง33นาที20วินาที |
| 100 | 18 ชั่วโมง20นาที | 30 ชั่วโมง33นาที20วินาที |

นี่เป็นเวลาจากสูตร ไม่ใช่การจับเวลาเล่นโดยมนุษย์ ไม่รวมตาย เดินทาง หรือ encounter eligibility จริง เป้าหมายคือสายใหม่เริ่มใช้ได้ก่อน masteryเต็ม แล้วใช้เวลาลงทุนเพื่อเชี่ยวชาญ ต้องทดสอบความสนุกและ pacing ก่อนยืนยันตัวเลขหรือโบนัส mastery

ตรวจ invariant ใน script ผ่าน4กลุ่ม: 1hit/sec กับ8hits/sec ได้เครดิตเท่ากัน; เปลี่ยนดาบ→ธนู→ดาบยังได้ดาบ700/ธนู300ตามวินาทีที่ฝึก; actionsที่ไม่เกิดผลได้0; 1วินาทีไม่เพิ่มแต้มอาวุธโจมตีหลายชนิดพร้อมกัน เป็น test ของแบบจำลอง ไม่ใช่ระบบ mastery ในเกมจริง

## 4. สลับอาวุธและสกิล

ยืนยัน: สลับได้เรื่อย ๆ **ไม่มีค่าใช้จ่ายหรือคูลดาวน์การสลับที่เพิ่มเข้ามา** คูลดาวน์สกิลที่ใช้ไปไม่รีเซ็ต

เก็บ cooldown ต่อ character_id + skill_id ไม่ผูกกับช่อง hotbar, weapon instance, หน้าต่าง, login session หรือการใส่ของ ต้องไม่ล้างจากถอดของ/ถือเล่มใหม่/เข้าใหม่ ช่วงโจมตีต้องรักษาความคืบหน้าหรือเวลาที่รอไว้ ไม่สลับเพื่อยิงเพิ่มทันที

แต่ละสกิลต้องระบุ lifetime ของผล:

| ชนิดผล | วิธีจัดการที่เสนอ |
|---|---|
| passive/ท่าประจำอาวุธ | ทำงานเฉพาะถือประเภทที่รองรับ ถอดแล้วจบทันที |
| บัฟตนเองที่ weapon_bound | ถอดอาวุธที่ต้องใช้แล้วจบ ไม่สลับสะสมหลายบัฟ |
| heal/บัฟปาร์ตี้ที่อนุญาตคงผล | ใช้ค่าที่ล็อกตอนร่ายและจบตามเวลา ไม่ได้พลังเพิ่มจากของที่ใส่ภายหลัง |
| projectile/DoT ที่ออกไปแล้ว | ใช้ต้นทางและ snapshot ของการใช้สกิลเดิม ไม่เปลี่ยนเป็นค่าสเตตัสอาวุธใหม่กลางทาง |
| channel/cast ที่ต้องถืออาวุธต่อเนื่อง | สลับแล้วหยุดตามนิยามสกิล ไม่คืน cooldown เพื่อ spam |

นี่เป็น template สำหรับเขียนรายสกิล ไม่ได้ตัดสินว่าทุกบัฟต้องจบตอนถอดทั้งหมด

## 5. การซื้อขายและไอเท็มบนพื้น

ยืนยัน: ไม่ bind ซื้อขาย ฝาก ส่งต่อ โยนทิ้งได้ รวมยูนีค ยูนีคที่หาย/ถูกทำลายไม่เปิดให้สร้างซ้ำ

ไอเท็มบนพื้นมี ground_instance record อ้าง item_instance_id เดิมและ expires_at = เวลาวางสำเร็จ + 30 นาที ใช้เวลาจาก server และบันทึกถาวร เปลี่ยนแผนที่ logout หรือ restart ไม่เริ่มเวลาใหม่ ถ้า serverปิดข้ามกำหนดต้อง expire ก่อนอนุญาตเก็บเมื่อเปิดใหม่

ตอนเก็บต้องแข่งกันแบบ atomic: ผู้เก็บคนแรกที่สำเร็จได้ของคนเดียว และต้องมี now < expires_at; ที่ deadlineหรือหลังจากนั้นหมดอายุ ตรวจที่ transaction ไม่พึ่งงานล้างพื้นอย่างเดียว กระเป๋าเต็มต้องไม่ลบจากพื้นหรือ resetอายุ การเก็บสำเร็จแล้วโยนใหม่เริ่มช่วงบนพื้น30นาทีรอบใหม่ แต่ยังเป็น itemชิ้นเดิม

owner protection ของของที่โยน, trade distance และเงื่อนไข storage ยังไม่ได้กำหนด อย่าเพิ่มข้อจำกัดโดยเรียกว่าผู้ใช้ยืนยันแล้ว

## 6. พัฒนา/ซ่อม/ย่อย/เศรษฐกิจ

ยืนยัน: แยกสิ่งเปลี่ยน stat กับรูปลักษณ์ ใช้ระบบหลักให้น้อย สุ่มรูปแดงเฉพาะสร้าง item ใหม่สำเร็จ ซ่อม/ตีบวก/เพิ่มพลังไม่สุ่มรูปใหม่ ไม่มี pity หรือจำนวนครั้งการันตียูนีค

ข้อเสนอ: เริ่มซ่อม + พัฒนาค่าสเตตัสชิ้นเดิมที่มี cap + ย่อย/ขาย NPC ยังไม่เปิด reroll affix/ย้ายรูปทรงอาวุธ/ระบบรูเสียบหลายชั้นพร้อมกัน ราคาซ่อม โอกาสตีบวกแตก durability floor วัตถุดิบที่ย่อยคืน และ buyback NPC ยังรอกำหนด ไม่ถือว่าผู้ใช้ยืนยันให้ตีบวกแตกหรือทำลายของอัตโนมัติแล้ว

ขายให้ผู้เล่นคือย้ายเจ้าของไม่ทำลาย ขายNPCต้องนิยามก่อนว่าทำลายทันทีหรือเข้า buyback ถ้ามี buyback ของต้องอยู่ใน locationที่ซื้อคืนได้เพียงแห่งเดียว หมดสิทธิ์ซื้อคืนจึง destroyed

คำอธิบายเรื่องเปลี่ยนรูปลักษณ์ล่าสุดของผู้ใช้หมายถึง **ตัวละครเดิมเปลี่ยนทรงผม/หน้าตาผ่านไอเท็ม** ไม่ใช่การยืนยันระบบย้ายสกินอาวุธ จึงไม่เปิดระบบคัดลอกรูปลักษณ์ยูนีคไป itemใหม่ในขอบเขตนี้

## 7. ร้านช่างและว่าจ้าง

ยืนยัน: ต้องปลดล็อก/ใช้งานสกิลเปิดร้านตีบวกก่อน จึงรับงานบริการผ่านร้านได้ มี2ทาง:

1. เช่าร้านที่ว่างในตลาด แล้วใช้สกิลเปิดร้าน ต้องจองสิทธิ์เช่าร้านพร้อมหักค่าเช่าแบบ atomic ไม่ให้มีช่าง2คนถือร้านเดียวกัน
2. ใช้ไอเท็มแผงลอย เปิดร้านตามจุดที่ผู้เล่นเลือก เมื่อปิดร้านแผงลอยหายไป ไม่ได้ไอเท็มแผงลอยกลับมา ข้อเสนอคือใช้แผงลอยเฉพาะเมื่อเปิดสำเร็จ ถ้าเปิดล้มเหลวไม่กินของ

ไม่ล็อกอาชีพช่างไว้เฉพาะเผ่า Nidavellir ตำแหน่งแผงลอยต้องไม่ทำให้คนอื่นเดินไม่ได้หรือบังปฏิสัมพันธ์ที่จำเป็น เสนอให้แผงไม่มี physical collision รายละเอียดซ้อนจุดต้องออกแบบ UI ไม่แอบตัดเงื่อนไขเปิดนอกตลาดที่ผู้ใช้ต้องการ

งานว่าจ้างมี job_id, crafter_character_id, customer_character_id, recipe_id, escrowวัตถุดิบ/ค่าจ้าง และผลลัพธ์ที่ผูกกับ job อย่างเดียว ผู้ว่าจ้างเป็นเจ้าของผลลัพธ์รวมยูนีคเสมอ ช่างมีชื่อเป็นผู้สร้าง ไม่ได้สิทธิ์เปลี่ยนเจ้าของผลลัพธ์เอง

ข้อเสนอ: ล็อกสูตร/ราคาที่ลูกค้ายอมรับและ snapshot level/skillช่างก่อนเริ่ม ชำระค่าจ้างและใช้วัสดุเมื่อ commitงานสำเร็จเท่านั้น ปิดร้านไม่ลบงานหรือกลืนของ escrow ต้องจบ/ยกเลิกตามสถานะและคืน/ส่งของด้วยขั้นตอนเดียวที่ทำซ้ำแล้วไม่จ่ายซ้ำ

ยังต้องกำหนด: ร้านทำงาน offlineได้ไหม, disconnect/เซิร์ฟเวอร์ปิดนับว่าปิดร้านหรือไม่, ค่าเช่า/ระยะเวลา, งานค้างตอนปิดร้าน และปลายทางส่งของเมื่อกระเป๋าเต็ม ทุกกรณีต้องมี recordถาวรก่อนเริ่มเปิดรับงานจริง

## 8. รหัสตัวละครและไอเท็ม

- character_id: รหัสถาวรจากserver ชื่อ เพศ ทรงผม สีตา สีผมเปลี่ยนได้ตามระบบที่กำหนดโดยไม่เปลี่ยนรหัส ไม่ใช้รูปหรือชื่อเป็น owner key
- item_instance_id: รหัสของอุปกรณ์ชิ้นจริง คงเดิมเมื่อ trade/drop/ซ่อม/ตีบวก แยกจาก item_template_id ที่บอกชนิดของ
- unique_design_id: รหัสแบบยูนีคแต่ละทรง ใช้ได้กับชนิดอาวุธที่กำหนด เก็บทะเบียนการสร้างสำเร็จเพียงครั้งเดียวทั่วขอบเขตเกมที่กำหนด ไม่ใช้ชื่อช่างหรือทรงผมเป็น key
- creator_character_id: ประวัติผู้สร้าง ไม่ใช่เจ้าของปัจจุบัน การลบตัวช่างไม่ลบผลงานที่อยู่กับลูกค้า เก็บ tombstoneประวัติเพื่ออ้างอิงรหัสที่ไม่ถูกนำมาใช้ซ้ำ

## 9. Invariant ของยูนีค

1. แต่ละ unique_design_id ถูกออกเป็นผลงานจริงได้ **ไม่เกินหนึ่งครั้งตลอดประวัติศาสตร์เกม** หลังออกแล้ว claimedคงอยู่ตลอด แม้ itemจะเหลือ0ชิ้น ไม่ต้องมีอยู่1ชิ้นเสมอ เพราะผู้ใช้อนุญาตให้สูญหายถาวร
2. item_instance_id มี locationปัจจุบันได้เพียงหนึ่งแห่ง: inventory / equipped / storage / ground / trade escrow / service escrow / delivery / destroyed ห้าม copy rowเพื่อย้ายของ
3. destroyedเป็นสถานะสิ้นสุด ไม่ลบทะเบียนuniqueแล้วสุ่มใหม่ ไม่มี reroll/pity/duplicate compensationที่สร้างตัวใหม่อีกชิ้น
4. สร้างitem, claimunique, ใช้วัสดุ, จ่ายค่าจ้าง, กำหนดเจ้าของ และบันทึกผลjob ต้อง commitพร้อมกัน พร้อมunique constraint และ keyป้องกันคำขอซ้ำ ถ้าจองก่อนผลิตยังไม่สำเร็จแล้วrollbackไม่ใช่การสร้างชิ้นจริง แต่ห้ามปลดclaimที่เคยcommitแล้ว
5. แก้ไข/reset/recovery/เครื่องมือGMต้องใช้ invariantเดียวกัน การคืน itemจากปัญหาระบบทำได้เฉพาะพิสูจน์ว่าเป็น instanceเดิมและไม่มีสำเนาที่อื่น ไม่ให้restoreสำรองบางส่วนจนของเดิมกับของคืนอยู่พร้อมกัน
6. ถ้าแยกหลายserverภายหลังและคำว่าเกมหมายถึงทุกserver ต้องมีทะเบียนกลางครอบคลุมทุกserver การuniqueแค่ฐานข้อมูลย่อยไม่เพียงพอ ตอนนี้ยังไม่อ้างว่าระบบdistributedนี้ถูกสร้างแล้ว
