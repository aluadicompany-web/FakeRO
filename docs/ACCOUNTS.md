# บัญชี ตัวละคร และGM

## เส้นทางเล่นจริง

สมัครชื่อบัญชี3–24ตัว ใช้ตัวอักษรอังกฤษ ตัวเลข และ_.- โดยขึ้นต้นด้วยตัวอักษรหรือตัวเลข ชื่อไม่แยกตัวพิมพ์เล็กใหญ่ รหัสผ่าน10–128ตัว ไม่ต้องใช้บริการอีเมลหรือOAuth เริ่มหนึ่งตัวละครต่อบัญชี ทุกเผ่าเริ่มCentralที่จุดเกิดจริงและผูกเมืองเกิดCentral ข้อมูลรูปลักษณ์ยังมีชาย/หญิง5ทรงผมต่อเพศ5สีตา6สีผม

หน้าสร้างตัวละครแยกจากหน้าสมัคร/ล็อกอิน มีการยืนยันรหัสผ่านตอนสมัคร กลับเข้าเกมด้วยบัญชีเดิมได้โดยไม่ต้องสร้างตัวละครใหม่ ตัวละครเก่าไม่ถูกย้ายตำแหน่งหรือรีเซ็ตเมื่ออัปเดต สามารถผูกตัวละครจากรหัสกู้คืนเดิมกับบัญชีว่างได้หนึ่งครั้ง เมื่อผูกแล้วรหัสกู้คืนเดิมใช้ล็อกอินลัดไม่ได้และsessionแบบเก่าถูกยกเลิก

## การเก็บข้อมูล

SQLiteเพิ่มตารางaccounts,account_sessions,gm_auditโดยไม่ลบheroes/sessions/world_stateเดิม รหัสผ่านใช้scryptแบบasyncพร้อมsaltสุ่ม16ไบต์ ไม่เก็บplaintext รหัสsessionสุ่ม32ไบต์และเก็บเฉพาะSHA256 Cookieเป็นHttpOnly/SameSiteStrictและเป็นSecureเมื่อกำหนดPUBLIC_ORIGINเป็นHTTPS อายุ30วัน

การสร้าง/ผูกตัวละครใช้transactionและhero_idเป็นUNIQUE ป้องกันคำสั่งพร้อมกันสร้างตัวที่สองหรือแย่งตัวละครที่มีเจ้าของแล้ว ตรวจOriginทุกPOST จำกัดความถี่API/การล็อกอิน และตรวจขนาดbody ห้ามให้clientกำหนดrole/เลเวล/ตำแหน่งตอนสร้าง ไม่มีรหัสผ่านหรือhashในresponse/snapshot

## GM

GMเป็นroleฝั่งฐานข้อมูล ทุกคำสั่งPOST/api/gmต้องมีaccount sessionที่ยังใช้ได้และrolegmจริง การปลอมปุ่มGMหรือส่งroleในJSONไม่ให้สิทธิ์ มีเครื่องมือวาร์ปแมพ ฟื้นHP และตั้งเลเวล1–120 คำสั่งตั้งเลเวลรีเซ็ตสเตตัสฐาน5และคืนแต้ม3ต่อเลเวลที่เพิ่ม เพื่อทดลองbuildใหม่ มีข้อความอธิบายบนปุ่มชัดเจน ทุกคำสั่งสำเร็จบันทึกactor/action/map/level/timeในgm_audit ไม่ได้เพิ่มคำสั่งGMผ่านWebSocket

`npm run gm:create -- --username worldkeeper` สร้างGMและรหัสสุ่มใน`.data/gm-credentials.txt` ไฟล์และฐานข้อมูลไม่รวมGit สำหรับdeploymentกำหนดGM_USERNAME/GM_PASSWORDในenvironmentเพื่อbootstrapบัญชีครั้งแรก โค้ดจะไม่ยกระดับบัญชีผู้เล่นชื่อเดียวกันและไม่เขียนทับรหัสเดิมเมื่อrestart ใช้CLIพร้อม--resetเพื่อเปลี่ยนรหัสGMและยกเลิกaccount sessionเก่าถ้าจำเป็น

## ขอบเขตและการทดสอบ

ยังไม่มีการกู้รหัสผ่านทางอีเมล การลบ/เปลี่ยนชื่อตัวละคร หรือหลายตัวละครต่อบัญชี บัญชีเก่าแบบrecoveryที่ยังไม่ผูกยังเข้าเกมแบบเดิมผ่านAPIได้เพื่อรองรับการย้ายข้อมูล แต่APIสร้างตัวละครใหม่ต้องเข้าสู่บัญชีเสมอ

`npm test`ผ่าน52กรณี รวมhash,ownership transaction,migration,Central spawnทุกเผ่า,HTTP/WS10คน,การปฏิเสธสิทธิ์GM,GM auditและsessionหลังlogout `npm run test:accounts`ทดสอบสมัคร/รหัสยืนยัน/แต่งตัว/สร้างตัว/ล็อกอินใหม่/reload/GM toolsผ่านเบราว์เซอร์ พร้อมภาพdesktop/mobileในartifacts/accounts DockerproductionทดสอบbootstrapGMและรักษาตัวละครในvolumeหลังrestartแล้ว
