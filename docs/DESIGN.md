# ข้อกำหนดและแผนพัฒนา

> แผนระบบหลักและกติกาล่าสุดของทั้งเกมดู [GAME-SYSTEMS.md](GAME-SYSTEMS.md) สูตรและพฤติกรรมต้นแบบด้านล่างยังไม่ใช่กติกาเป้าหมายล่าสุดทุกข้อ โดยเฉพาะ EXP การตาย และ PvP

## ทิศทางที่ตกลง

เว็บบนคอมก่อน เตรียมขยาย PC/mobile, คลิกเดินและคลิกโจมตี, ความเร็ว/ความยากเป้าหมายใกล้เกมคลาสสิก 8/10, เผ่ารูปร่างมนุษย์อิงนอร์สแทนคลาสหลัก, ไม่ล็อกอาวุธตามเผ่า, ทดสอบ PvE ไม่เกิน 10 คน, ไม่มีงบเช่า server

เกมต้องเก็บโลกและกติกาแยกจาก renderer เสมอ Input ส่ง action ไม่ส่งผลลัพธ์ การแตะและคลิกใช้เส้นทางเดียวกัน เปลี่ยนไป wrapper บน PC/mobile ภายหลังได้โดยไม่ย้าย simulation ไป client แต่ต้องทดสอบประสิทธิภาพ/พื้นที่จอใหม่ ไม่ใช่แค่ export แอป

## สูตรต้นแบบ v0.1

ค่าฐานทุก stat=5, โบนัส stat ประจำเผ่า=3+floor((level−1)/5), อัปได้ 3 แต้มต่อเลเวล ค่า base stat สูงสุด 60, level cap 50 ไม่มีซื้อแต้ม/reset ในต้นแบบ

- EXP ขึ้นเลเวล = floor(45 × level^1.65) เก็บ EXP ส่วนเกินข้ามหลายเลเวล
- HP สูงสุด = 90 + 12×level + 8×VIT
- ATK = 8 + 2×level + 2×STR + 0.4×DEX
- MATK = 8 + 2×level + 2×INT + 0.4×DEX
- DEF = 0.7×VIT + 0.5×level
- ช่วงโจมตี = max(450, 1100−12×AGI) ms
- Critical = min(30%, 2%+0.3%×LUK), damage ×1.5
- ความเร็วเดิน = 2.3 หน่วย/วินาที ระยะโจมตี 1.4 หน่วย ทั้งสองโหมดในต้นแบบ
- มอนสเตอร์ระดับ 1: HP75, EXP15; ระดับ 3: HP145, EXP32; respawn 9 วินาที
- มอนสเตอร์โจมตีกลับทุก 1.3 วินาทีเมื่อถูก engage และอยู่ใกล้ (1.6 หน่วย)
- การตาย: ฟื้นที่ศาลา ไม่มีโทษช่วงทดสอบ; ศาลาฟื้น 20 HP/วินาที

นี่คือ baseline ที่ตรวจสอบได้ ไม่ใช่สมดุลสุดท้าย งบ stat เท่ากันไม่ได้แปลว่า DPS/EHP เท่ากัน `npm run balance` แสดงความต่างช่วงเริ่มต้น STR/INT ได้ DPS มากกว่า DEX/AGI/LUK ในระบบ auto-attack ปัจจุบัน ต้องมีระยะอาวุธ ความแม่นยำ สกิล และประโยชน์เศรษฐกิจก่อนตัดสินความคุ้มของแต่ละสาย ไม่แก้ให้ผ่านด้วยการเรียกทุกเผ่าว่าสมดุล

## การทดสอบบาลานซ์ระยะถัดไป

วัดเวลาเดินและฆ่า เวลาเสียชีวิต HP ที่เสียต่อ EXP, การฟื้น, เลเวลต่อชั่วโมง และประโยชน์ในปาร์ตี้ โดยใช้ build งบแต้มเท่ากันที่เลเวล 1/5/10/20 กับศัตรูหลายแบบ ตั้งเป้า build ที่ทำบทบาทเดียวกันมีประสิทธิภาพต่างไม่เกินราว 10–15% ก่อน playtest จริง แล้วปรับจากข้อมูล ไม่เร่ง curve ทั้งเกมตามความรู้สึกจากมอนสเตอร์เดียว ความยากเป้าหมาย 8/10 ยังไม่ได้รับการยืนยัน

## ขอบเขตความปลอดภัย

เซิร์ฟเวอร์ไม่รับ level, EXP, damage, HP หรือผลการฆ่าจาก client ตรวจ finite coordinates, clamp ขอบโลก, คุมความเร็ว, range, cooldown, แต้มและ cap เอง รับ input ไม่เกิน 25 messages/วินาที/connection; จำกัด body/payload; HTTP auth จำกัดต่อ IP; กำหนด origin; session cookie HttpOnly + SameSite=Strict; recovery และ session เก็บเป็น SHA-256 ของ token สุ่ม 256 บิต ไม่ใช้รหัสผ่านที่ผู้ใช้คิดเอง

ห้ามเข้า character เดียวหลาย socket ป้องกัน save ทับกัน จำกัดโลก 10 คน มี ping ตรวจ socket ที่ค้าง บันทึกทุกวินาทีและเมื่อ disconnect ใช้แต้มและ shutdown ปกติ SQLite อยู่เครื่องเดียว ไม่รองรับ cluster ระดับนี้ไม่มี ownership ของไอเทมหรือระบบซื้อขาย จึงยังไม่อ้างว่าป้องกัน duplication ในระบบที่ยังไม่สร้าง

ข้อจำกัด: สร้างบัญชี guest จำนวนมากได้ตามเวลา ไม่มี CAPTCHA/email verification; ไม่มีกู้คืนหากรหัสหาย; token ถูกขโมยยังใช้แทนเจ้าของได้; ไม่มี centralized logging/ban/backup automation; ยังไม่ผ่าน penetration test เครือข่ายสาธารณะ จึงให้เริ่มจากกลุ่มเชื่อถือได้ ผู้ที่ตีครั้งสุดท้ายได้ EXP; party sharing/anti kill-steal ยังไม่มี

## ลำดับพัฒนาต่อ

1. ตรวจความรู้สึกการเดิน/ต่อสู้กับผู้ใช้ 2–10 คน เพิ่ม hit feedback, selection, collision/pathfinding (ต้นแบบเดินเส้นตรง scenery ไม่มี collision), หน้าตัดการเชื่อมต่อและผลทดสอบ latency
2. ทำ sprite คน/มอนสเตอร์แยกทิศทางและฉากต้นฉบับของเกม ตั้งงบ asset สำหรับมือถือ แยกโหลด Phaser/world เมื่อจำเป็น
3. เพิ่มสกิลเอกลักษณ์เผ่า, อาวุธที่ทุกเผ่าใช้ได้, enemy archetypes และ simulation ประเมิน EHP/DPS/utility จึงปรับเป้าหมายความยาก
4. เพิ่ม inventory/drop เป็นธุรกรรม พร้อม tests double submit, reconnect, full bag, crash recovery ก่อนเพิ่มซื้อขาย
5. ปาร์ตี้, XP sharing, threat และ healer/support loop; ขยาย map ตามข้อมูล ไม่ขยายจำนวนผู้เล่นก่อน profiling
6. โฮสต์ HTTPS, backup/restore drill, abuse controls, บัญชีถาวร/การกู้คืนที่เหมาะสม ก่อนเปิดนอกกลุ่มทดสอบ
7. หลัง browser เสถียรจึงประเมิน desktop wrapper และ mobile packaging โดยใช้ protocol/rules ชุดเดิม
