# Art direction · Revision 4 — directional character components

ภาพเป้าหมายคือ Classic Japanese SD / chibi JRPG anime ประมาณ 3 หัว เส้นสีน้ำตาลเข้ม ดวงตาอนิเมะ ช่อผมชัด ผ้า หนังและโลหะมีแสงเงา คงชุดเริ่มต้น 6 เผ่า: Muspelborn แดง, Ljosalfar เขียว, Jotunborn ฟ้า–ขาวสายสนับสนุน, Vanirkin ม่วง, Nidavellir ทอง และ Skuggar ดำ ทุกเผ่าใช้ระบบอาวุธเดียวกัน

ภาพ RO ที่ผู้ใช้ส่งเป็นตัวอย่างโครงสร้าง: แยกหัวจากชุด แต่ผูกด้วยตำแหน่งคอและทิศเดียวกัน ไม่ได้นำ sprite ของ RO มาแจกจ่ายในเกม ภาพเพิ่มเติมเป็นงานใหม่ที่ต่อจากคอนเซปต์เดิมของ FakeRO

## ปัญหาเดิมและโครงสร้างใหม่

รุ่น 3 มีเพียงภาพหน้าเฉียง/หลัง แล้วกลับด้านและบีบภาพเพื่อแทนมุมอื่น แขนถูกเรียกตามด้านบนจอ ทำให้การถือมือขวาและการซ้อนอาวุธเปลี่ยนความหมายเมื่อเปลี่ยนมุม รุ่น 4 ใช้ภาพประกอบที่ลงทะเบียนครบ 8 ทิศ ไม่มีการพลิกทั้ง rig หรือบีบตัวละครเพื่อทำมุมข้าง แต่ละทิศระบุคอ ไหล่ ศอก ฝ่ามือ สะโพก เท้า และแขนด้านใกล้/ไกล

- ชุด 96 เฟรม = 6 เผ่า × 2 เพศ × 8 ทิศ หัว 80 เฟรม = 5 ทรง × 2 เพศ × 8 ทิศ
- มีภาพวาดฐาน 5 มุม: หน้า, เฉียงหน้า, ข้าง, เฉียงหลัง, หลัง รวม 60 มุมชุด / 50 มุมหัว อีก 3 ทิศสะท้อนจากภาพฐานแล้วจัดตำแหน่งแขนใหม่ให้ลักษณะเครื่องแต่งกายของแขนขวา/ซ้ายอยู่กับแขนเดิม ไม่สะท้อนตัวละครทั้งตัวตอนแสดงผล
- `armR` คือแขนขวาของตัวละครเสมอ อาวุธหลักอยู่แขนนี้ทุกทิศ โล่/อาวุธรองอยู่ `armL` อาวุธอยู่ระหว่างชั้นแขนกับถุงมือ แขนไกลซ่อนหลังลำตัวในมุมข้าง แขนทั้งสองอยู่หน้าลำตัวในมุมตรง
- หัวแยกหน้า ผมหน้า ผมหลัง ม่านตา และเปลือกตา ผมหลังอยู่ใต้ชุดในมุมหน้าและคลุมชุดในมุมหลัง สามารถเปลี่ยนผม 6 สีและตา 5 สีโดยไม่ย้อมผิว/เสื้อ มีลืมตา หลับตา หรี่ตา และกะพริบแบบเหลื่อมจังหวะระหว่างตัวละคร
- ชุดแยกลำตัว ชายผ้า แขนซ้าย/ขวา ถุงมือ ขาและรองเท้า รวม 10 ชิ้นหลัก และภาพต้นแขน/ปลายแขนอีก 4 ชิ้นเพื่อขยับศอก ระบบสองข้อต่อใช้ศอก/ฝ่ามือของภาพนั้นจริง

จำนวนเหล่านี้เป็น **เฟรมทิศทางและชิ้นส่วน** ไม่ใช่จำนวนท่าโจมตีที่วาดทีละเฟรม ท่ายืน เดิน โจมตี ร่ายเวท รับดาเมจและล้มยังประกอบด้วย keyed poses/rig อาวุธใช้คอมโบ 2/3/4 จังหวะตามความเร็วจากเซิร์ฟเวอร์ การเดินสัมพันธ์กับระยะเคลื่อนที่บนพื้น ส่วนหัวและชายผ้าขยับเบา ๆ แยกจากชุด ระบบนี้เพิ่มความละเอียดโดยไม่ต้องสร้างไฟล์ภาพใหม่สำหรับรูปลักษณ์ทั้ง 1,800 แบบทุกท่า

## ไฟล์และขั้นตอนเตรียมภาพ

ภาพต้นฉบับเพิ่มเติมอยู่ใน `docs/art/characters-v4-{heads,components,profile}-source.png` ภาพเฉียงหน้า/หลังที่ยอมรับไว้เดิมยังเป็นแหล่งเตรียมภาพใน `public/art/characters/` และต้นฉบับรุ่น 3 ใน `docs/art/` ห้ามลบก่อนย้ายแหล่งอ้างอิงของ packer

รัน `npm run art:characters:v4` โดยใช้ Python 3, Pillow และ NumPy เพื่อแบ่งส่วนโปร่งใส ปรับสเกล/จุดเท้า แยก masks และจัด atlas แบบ trimmed สคริปต์ตรวจว่าส่วนลำตัว/แขน/ขา/ถุงมือ/รองเท้า/ผ้ารวมกลับแล้วไม่มีพิกเซลต้นฉบับตกหล่น; ค่านี้ไม่ใช่การรับรองคุณภาพภาพวาด ต้องตรวจด้วยตาในเกมด้วย

ผลลัพธ์อยู่ `public/art/characters-v4/`:

- `body-atlas.webp` + JSON: 1,344 entries ของ 14 ชิ้น × 96 เฟรม
- `head-atlas.webp` + JSON: 480 entries ของหน้า/ผมหน้า/ผมหลัง/ม่านตา และเปลือกตา 2 แบบ × 80 เฟรม
- ทั้งสอง atlas โหลดใน Phaser ใช้พื้นที่ RGBA ประมาณ 12 MiB รวมกัน metadata เก็บตำแหน่งตัดและขนาดต้นฉบับ 128×192 จึงไม่เสียจุดยึดเมื่อ trim
- `costumes.webp`, `heads-*.webp`: grid สำหรับ SVG ในหน้าสร้างตัวละครและภาพโปรไฟล์ เป็นภาพชุดเดียวกับในเกม ไม่ใช่ตัววาดคนละระบบ
- `manifest.json`: สรุปจำนวน/ขนาด; `shared/character-rig.json`: จุดยึดและลำดับชั้น; `shared/character-art.ts`: ดัชนีร่วมและสีหน้า

เฟรมชุด = `facing * 12 + sex * 6 + race`, เฟรมหัว = `facing * 10 + sex * 5 + hairstyle`; เพศชาย = 0, หญิง = 1 ทิศเรียง E, SE, S, SW, W, NW, N, NE ทุกหน้าต่างเริ่มแสดงมุม SE เหมือนคอนเซปต์เดิม

## การตรวจและการขยายต่อ

หน้าสร้างและกระเป๋ามีปุ่มหมุน 8 ทิศ บัญชี GM เปิด **เครื่องมือ GM → ตรวจชิ้นส่วนตัวละคร / 8 ทิศ** เพื่อเลือกเผ่า เพศ ทรง/สีผม สีตา อาวุธ มุม ท่า ส่วนภาพ สีหน้าและจุดต่อได้ หน้าตรวจใช้ HeroRig ตัวเดียวกับเกม แต่สำเนาข้อมูลในหน่วยความจำ ไม่ส่งการแก้ไขตัวละครไปเซิร์ฟเวอร์ โลกเกมยังเดินเวลาตามปกติ

- `npm test`: ดัชนีครบทุกทิศ, จุดยึด, ความครบของพิกเซล, atlas budget, สีหน้า และกติกาเกม
- `npm run test:character-v4`: GM workshop, แยก 9 รูปแบบส่วนภาพ, 3 สีหน้า, 12 ชุด, 6 ท่า, หมุนในหน้าสร้าง/กระเป๋า, มือถือ และตรวจข้อมูลบัญชีไม่เปลี่ยน
- `npm run test:character-art`: หน้าสร้างครบ 12 ชุด/10 ทรง/6 สีผม/5 สีตา, โปรไฟล์, เข้าแมพ/ต่อสู้/กลับมาเล่นและมือถือ
- `npm run test:weapon-grip`, `test:refinement`, `test:combo-combat`: ภาพถืออาวุธ, เดินจริง 8 ทิศ และคอมโบเซิร์ฟเวอร์ 17 แบบอาวุธ

ภาพหลักฐานอยู่ `artifacts/characters-v4/` (ไม่รวม Git) การเพิ่มหมวก/ชุดชิ้นใหม่ภายหลังต้องเตรียมครบ 8 ทิศและระบุจุดยึด รวมถึงตรวจว่าชุดเดิมไม่ทะลุชิ้นใหม่ ไม่ควรใช้การหมุนภาพเดียวแทนมุมใหม่

คง schema `appearance: {gender,hair,eyes,hairColor}` และตัวเลือก 1,800 รูปลักษณ์ ตัวละครเดิมใช้ภาพใหม่ทันที ไม่เปลี่ยน ID บัญชี เลเวล สเตตัส ของหรือความคืบหน้า ไม่มี migration ฐานข้อมูลในงานนี้

## ผลตรวจรอบรุ่น 4

ตรวจด้วย Node 24, TypeScript และ Chromium/WebGL: build ผ่าน, unit tests 78/78, creator/portrait/world/persistence ผ่าน, GM workshop ครบ 8 ทิศ/9 ส่วนภาพ/3 สีหน้า/12 ชุด/6 ท่า, ตรวจค้างท่าแล้วหมุนกลับได้ภาพตรงกัน, เดินจริง 8 ทิศและกระเป๋า 6 ขนาดจอผ่าน, ต่อสู้จริงครบ 17 อาวุธโดยเซิร์ฟเวอร์กำหนดคอมโบ/คูลดาวน์ ไม่มี page error หรือภาพ 404 ในรอบที่ผ่าน และตรวจ PNG/WebP แบบ lossless ตรงกันทั้ง 8 ไฟล์

`test:refinement` มีการรอช่วงเดินสั้นจาก DOM: การรันพร้อมหลาย Chromium บน software GPU ทำให้ timeout ระหว่างตรวจทิศ 2 รอบ; รันแยกโดยไม่เปลี่ยนเกมหรือเงื่อนไขทดสอบแล้วผ่านครบ 8 ทิศ ควรรัน browser suites ที่หนักแยกกันเพื่อหลีกเลี่ยงการพลาดช่วง animation นี้
