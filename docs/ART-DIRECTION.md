# Art direction · Revision 5 — painted frame animation

ตัวละครเป็น SD อนิเมะ JRPG ประมาณ 3 หัว เส้นน้ำตาลเข้ม ผ้า หนังและโลหะมีแสงเงา คงชุดเริ่มต้นชาย–หญิงของ Muspelborn แดง, Ljosalfar เขียว, Jotunborn ฟ้า–ขาวสายสนับสนุน, Vanirkin ม่วง, Nidavellir ทอง และ Skuggar ดำ

## สิ่งที่เปลี่ยนจากรุ่น 4

รุ่น 4 ขยับแขน/ขา/ชายผ้าด้วยข้อต่อและ inverse kinematics รุ่น 5 เปลี่ยนเป็น **ภาพชุดเต็มตัวที่วาดท่าใหม่ แล้วเปลี่ยนเฟรมตามเวลา** ไม่มีการเรียก ArticulatedArm, solveArm หรือ sampleAttackPose ในตัวเรนเดอร์ตัวละคร และไม่มีการหมุนภาพลำตัวเพื่อแทนท่าเดิน ฟัน โดนตี หรือล้ม

ภาพใหม่มาจากแผงภาพที่สร้างโดยยึดชุดที่อนุมัติไว้เป็น reference ไม่ใช่การบันทึก rig เดิมลง PNG และไม่ได้นำ sprite ของ Ragnarok มาแจกจ่ายในเกม

## ภาพและการประกอบ

- ชุดเต็มตัว **1,536 เฟรม = 12 ชุด × 8 ทิศ × 16 ท่าฐาน** มีต้นฉบับ 18 แผง: 12 แผงเพศ/เผ่าใน 5 มุม และ 6 แผงมุมซ้ายของทั้งสองเพศอีก 3 มุม
- ท่าฐาน: ยืน, หายใจ, เดินซ้ายลงเท้า/ผ่าน, เดินขวาลงเท้า/ผ่าน, เตรียมฟัน, ฟันปะทะ, ฟันตาม, ฟันย้อน, แทง, โจมตีเหนือหัว, รวมพลัง, ปล่อยเวท, โดนตี และนอนล้ม
- ภาพเดินใช้ 4 เฟรมตามระยะทางจริง ท่าโจมตีเลือกเฟรมเตรียม/ปะทะ/ตาม/คืนท่าตาม clip และคอมโบที่เซิร์ฟเวอร์ส่ง ไม่ใช้เวลาของ client มาตัดสินดาเมจ
- เฟรมท่าเหล่านี้เป็นคลังท่าร่วมสำหรับอาวุธ 17 แบบ ไม่ได้อ้างว่ามีภาพวาดชุดโจมตีอิสระแยกใหม่ครบทุกอาวุธและทุกไอเท็ม อาวุธยังใช้ภาพอุปกรณ์เดิม วางและกำหนดมุมตามฝ่ามือของแต่ละเฟรม ไม่มีข้อต่อแขนคอยยืดหามัน
- ศีรษะใช้โมดูลภาพเดิม 80 มุม แยกหน้า ผมหน้า ผมหลัง ม่านตาและเปลือกตา จัดตำแหน่งตามจุดคอของแต่ละเฟรมชุด จึงคงทรงผม 5 แบบต่อเพศ ผม 6 สีและตา 5 สีได้ ไม่ได้วาดทรงผมใหม่ซ้ำสำหรับทุกเฟรมชุด
- ภาพหัวล้มเตรียมเป็น texture แนวนอนซ้าย/ขวารอบจุดคอ แยกจากภาพยืน ตัวเกมเลือก texture นี้โดยไม่หมุนข้อต่อหัวตอนแสดงศพ ตัวละครล้มยังมองเห็นจนกว่าจะคืนชีพ/ย้ายตามกติกาเกม
- อาวุธหลักยึด `right` และโล่/อาวุธรองยึด `left` ใน metadata ของเฟรม มีภาพมือปิดทับด้ามจับแยกจากภาพชุดเต็มตัว

ตัวเรนเดอร์ยังชื่อ `HeroRig` เพื่อคง API ของฉากและเครื่องมือตรวจ แต่ภายในเป็น frame player ไม่ใช่โครงกระดูกแบบรุ่น 4

## ต้นฉบับและการเตรียมซ้ำ

ภาพอยู่ `docs/art/characters-v5/` มีจุดสีเขียวที่คอและสีฟ้าที่ฝ่ามือสำหรับ registration ภาพเหล่านี้เป็นไฟล์เตรียมงาน ไม่ได้โหลดในเกม สคริปต์แยกจุดกำกับออกและคืนสีจากบริเวณรอบจุดก่อนจัด atlas

รัน `npm run art:characters:v5` โดยใช้ Python 3, Pillow และ NumPy สคริปต์ `scripts/pack-character-v5.py` ตรวจจำนวนแถวจริงจาก alpha ก่อนตัดกริด ตัดเศษภาพจากช่องข้างเคียงด้วย connected components ตรวจว่าจุดจับหลักทับพิกเซลตัวละคร และใช้สเกลร่วมต่อแถบท่าของชุด ไม่ปรับขนาดแยกทีละท่า จัดพื้นเท้าและคอ แล้ว trim เก็บขนาดต้นฉบับ 192×192 ไว้ใน atlas JSON

ไฟล์ที่ใช้จริงอยู่ `public/art/characters-v5/`:

- `body-male.webp` / `body-female.webp` + JSON: ชุดเต็มตัวและมือปิดทับอาวุธ
- `head.webp` + JSON: โมดูลหัวปกติ/ล้มและสีหน้า
- `costumes.webp`: เฟรมยืนที่ใช้ใน SVG ของหน้าสร้างตัวละครและภาพโปรไฟล์ จึงใช้ชุดเดียวกับแมพ
- `manifest.json`: จำนวนและขนาด texture; `registration-report.json`: จุดกำกับที่ไม่ครบ/มือที่ถูกบัง ซึ่งใช้ตำแหน่งอ้างอิงจากเฟรมยืน ไม่ใช่การรับรองว่าทุกจุดจับผ่านการตรวจด้วยตาแล้ว
- `shared/character-animation.json`: จุดคอ/ฝ่ามือ ต้นฉบับ แถวและคอลัมน์ของทุกเฟรม
- `docs/art/characters-v5/registration-overrides.json`: ตำแหน่งมือที่ถูกบัง 2 เฟรม พร้อมการวางอาวุธหลังลำตัว
- `shared/character-animation.ts`: ลำดับภาพ การเดินตามระยะทาง และการจับจังหวะปะทะ

ID เฟรม = `(facing * 12 + sex * 6 + race) * 16 + pose`; ทิศเรียง E, SE, S, SW, W, NW, N, NE เพศชาย=0 หญิง=1

ไฟล์รุ่น 3/4 เก็บเป็นแหล่งอ้างอิงชุดและหัว/ระบบเตรียมภาพเดิม ไม่โหลด atlas แขน/ขาของรุ่น 4 ในแมพอีก

## เครื่องมือตรวจและการทดสอบ

GM เปิด **เครื่องมือ GM → ตรวจชิ้นส่วนตัวละคร / 8 ทิศ** เพื่อเลือกชุด เพศ ทรง/สีผม สีตา อาวุธ ท่า สีหน้าและจุดคอ/มือ พร้อมหยุดภาพแล้วหมุนตรวจได้ ตัวเลือกภาพแยกเป็นหัว ผม และชุดเต็มตัวตามรูปแบบ sprite ใหม่ การตรวจเป็นสำเนาในหน่วยความจำ ไม่ส่งการแก้ไขไปบัญชีจริง โลกเกมยังเดินเวลาตามปกติ

- `npm test`: โครงสร้าง 1,536 เฟรม, ต้นฉบับครบ 8 ทิศ, ลำดับลงเท้า, การเลือกเฟรมปะทะที่เวลา hit ของทั้ง 17 อาวุธ และกติกาเกม
- `npm run test:character-frames`: หน้าตรวจ GM, การหมุน, สีหน้า, ชุดชาย/หญิง, ทุก action, มือถือ และตรวจว่าข้อมูลจริงไม่เปลี่ยน
- `npm run test:character-art`: หน้าสร้าง 12 ชุด/10 ทรง/6 สีผม/5 สีตา, ภาพโปรไฟล์, เข้าแมพ ต่อสู้ และกลับมาเล่น
- `npm run test:weapon-grip`, `test:combo-animation`: ภาพท่าใน renderer จริง
- `npm run test:refinement`: กระเป๋า/โล่/อาวุธสองมือ/เดินจริง 8 ทิศ/6 ขนาดจอ
- `npm run test:combo-combat`: การต่อสู้เซิร์ฟเวอร์จริงครบ 17 อาวุธและคูลดาวน์สลับอาวุธ

ควรรัน browser suites ที่หนักแยกกันบน software GPU เพราะการจับช่วงเดินสั้นจาก DOM อาจพลาดเมื่อหลาย Chromium แย่งเวลาประมวลผล ภาพหลักฐานอยู่ `artifacts/characters-v5/` และโฟลเดอร์ของแต่ละ suite ซึ่งไม่รวม Git

คง schema `appearance: {gender,hair,eyes,hairColor}` และรูปลักษณ์ 1,800 แบบ ไม่เปลี่ยน ID บัญชี เลเวล สเตตัส ของหรือความคืบหน้า ไม่มี migration ฐานข้อมูลในงานนี้

## ผลตรวจรุ่น 5

Build ผ่านและ unit tests ผ่าน 85/85 ตัวเรนเดอร์เปิดครบ 1,536 เฟรมและตรวจว่าไม่มีการหมุนข้อต่อลำตัว/แขน พร้อมตรวจลำดับภาพของอาวุธที่อยู่หลังตัวละครในเฟรมมือถูกบัง การเตรียมภาพตรวจว่าฝ่ามือหลักของทุกเฟรมที่ถืออาวุธอยู่บนพิกเซลตัวละคร

ผ่าน browser suites: GM workshop/หยุดภาพแล้วหมุนกลับ, 12 ชุดและตัวเลือกผม/ตาทั้งหมด, สร้างตัวละครและกลับมาเล่น, ต่อสู้จริง 17 อาวุธด้วยคอมโบช้า 2 จังหวะ/เร็ว 4 จังหวะโดยไม่รีเซ็ตคูลดาวน์, กระเป๋า/โล่/อาวุธสองมือ/เดิน 8 ทิศ/6 ขนาดจอ ไม่พบ page error หรือภาพ 404 ในรอบที่ผ่าน Texture ตัวละครใช้ RGBA รวม 72 MiB แบ่งชาย/หญิง 2048×4096 และหัว 2048×1024
